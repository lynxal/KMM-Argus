# argus-webui CI + move Verify onto the self-hosted runner

> **Outcome — read this before the plan below.** Everything for #17 landed:
> `.github/workflows/verify-webui.yml` runs lint, typecheck, 88 vitest assertions and three headless
> Chromium probes, blocking, paths-filtered. **Task 6 did not happen** — the self-hosted runner move
> was declined on evidence. `[self-hosted, android-build]` will not serve `KMM-Argus` because Argus
> is public and runner groups do not allow public repositories by default; the box also builds and
> Firebase-distributes Canvas's Android releases, so letting fork PRs execute on it is not a trade
> worth making. `verify.yml` stays on `ubuntu-latest`. Full reasoning and the ruled-out alternatives
> are in `shape.md` → "The self-hosted runner question, answered". The plan below is preserved as
> approved, so the parts about `[self-hosted, android-build]` and `android-actions/setup-android@v3`
> describe what *would* have been done.


## Context

Issue [#17](https://github.com/lynxal/KMM-Argus/issues/17): `argus-webui` has no CI job at all.
`.github/workflows/verify.yml` is Gradle-only — no `setup-node`, no `npm ci`, no `npm test`. A PR can
break the whole Web UI, including the 88 vitest assertions that already exist and pass locally, and
CI stays green. Every DOM-layer bug in this UI so far (#13, #15, #8) was caught by a human driving a
browser, with the harness thrown away afterwards — except that three of those harnesses were kept:
`scripts/probe-webui/{follow-tail,related-logs,version}-probe.js` fake the device in-process via
`fake-device.js` and need no device and no host app, only a built `dist/`.

Second half of the ask: `lynxal` has org-level self-hosted runners, and Argus workflows should use
them where Apple hardware isn't required.

Intended outcome: a `Verify (Web UI)` check that compiles, lints, unit-tests and browser-probes the
Web UI on every PR that touches it, plus `verify.yml` moved off GitHub-hosted minutes onto the
self-hosted Linux box.

## What was established during shaping

**The runner exists and is reachable.** `[self-hosted, android-build]` → `Aveli-Gazan-Android`,
runner group `default`, **Linux x64**, workspace `/home/github-runner/actions-runner-android/_work`.
No repo in the org has repo-level runners (`/repos/*/actions/runners` → `total_count: 0` for
`canvas_control_mobile`, `canvas_hub_core_application`, `canvas_firmware`), so these are org-level in
the Default group — reachable from `KMM-Argus` unless an admin has narrowed that group's visibility.
That last bit is the one thing not confirmable from here (the org runners API needs `admin:org`), so
Task 2 confirms it with a real dispatch before anything else is built on top.

Other org labels, for the record: `[self-hosted, rpi, ARM64]`, `[self-hosted, linux, x64, firmware-build]`.
Neither fits a Gradle/Android build.

**`git` IS on the runner, despite the comments in `canvas_control_mobile`.** Three of its workflows
carry comments saying "the self-hosted runner has no git on PATH, so actions/checkout downloads a
source tarball (no .git, no history)". The 2026-08-20 run log for that repo shows
`/usr/bin/git clone`, `git clean -ffdx`, `git fetch --depth=1` — a normal git checkout. Those
comments are stale. Two consequences: nothing in Argus needs a REST-API workaround, and `git clean
-ffdx` wipes every `build/` dir between runs, so the persistent workspace cannot serve stale AGP
`intermediates`.

**The Android SDK is not preinstalled the way it is on `ubuntu-latest`.** `canvas_control_mobile`
adds `android-actions/setup-android@v3` explicitly. `verify.yml` builds `:sample:assembleDebug`, so
it needs that step added as part of the move. `actions/setup-java` tool-cache downloads work fine on
the box (`_work/_tool/Java_Zulu_jdk/17.0.20-8/x64` in the logs).

**`npm run lint` fails on a clean checkout — a real bug, not a CI detail.** `argus-webui/tailwind.config.ts:2`
imports `./src/design/tokens.json`; that file is generated by `npm run tokens`
(`scripts/build-tokens.ts`) and is gitignored at `argus-webui/.gitignore:7`. `lint` is
`tsx scripts/lint-tokens.ts && tsc --noEmit` with no tokens step. Verified on the clean tree:

```
token lint: clean
tailwind.config.ts(2,20): error TS2307: Cannot find module './src/design/tokens.json'
```

`build` already does `npm run tokens && tsc --noEmit && vite build`, which is why nobody hits this.

**Tier 2 is far cheaper than #17 estimated.** Measured on this machine against a clean `npm ci`:

| Step | Time | Result |
|---|---|---|
| `npm run build` (argus-webui) | 3.1 s | ok |
| `npm test` | 0.4 s | 9 files, 88 tests, all pass |
| `node version-probe.js` | 1.0 s | pass |
| `node related-logs-probe.js` | 2.2 s | pass, 9 assertions |
| `node follow-tail-probe.js` | 6.5 s | pass, 6 injections + 8 checks |

All three probes bind an ephemeral loopback port via `fake-device.js` (observed `127.0.0.1:58900`),
so there is no fixed-port collision with anything else on the runner. Playwright is lockfile-pinned
at **1.60.0** in `scripts/probe-webui/package-lock.json`, so the browser cache key is stable.

**Decisions taken with you:** separate paths-filtered `verify-webui.yml`; all three self-contained
probes; blocking (no `continue-on-error`); `verify.yml` → self-hosted; `verifyIos.yml` and
`publishToMavenCentral.yml` stay on `macos-latest`.

## The one genuine unknown, and its fallback

Whether headless Chromium launches on that box. `npx playwright install chromium` downloads the
browser but not the system shared libraries; `--with-deps` shells out to `sudo apt-get`, which on a
shared self-hosted runner may have no passwordless sudo and would mutate a machine other repos
depend on. Task 2 answers this empirically. If Chromium cannot launch:

1. Preferred — ask the runner admin to run `npx playwright install-deps chromium` once on the box.
2. Fallback that needs no admin — split `verify-webui.yml` into two jobs: `unit`
   (`[self-hosted, android-build]`) and `probes` (`ubuntu-latest`, where `--with-deps` works).

Either way Tier 1 lands on the self-hosted runner.

## Tasks

### Task 1 — Save spec documentation

Create `agent-os/specs/2026-08-20-1301-webui-ci-and-self-hosted-runners/` with `plan.md` (this file),
`shape.md`, `standards.md`, `references.md`. No `visuals/` — none provided, none relevant.

`standards.md` carries the two entries from `agent-os/standards/index.yml` that actually apply:
`testing/test-structure` and `workflow/commit-conventions`. This repo's standards index has **no
`ci/` category** — `ci/actions-node-runtime` lives in `lynxal/canvas-cm`, not here — so record the
absence rather than inventing a local standard.

`references.md` records: `lynxal/canvas_control_mobile/.github/workflows/publishDev.yml` +
`nightlyDev.yml` (the only in-org precedent for `[self-hosted, android-build]`, including the stale
no-git comments and the `setup-android` step), and `scripts/probe-webui/README.md` (the recorded
reason `ui-probe.js`/`ws-probe.js` stay manual).

### Task 2 — Confirm the runner is reachable and can run the job (do this first)

A throwaway `workflow_dispatch` workflow on this branch, `runs-on: [self-hosted, android-build]`,
that prints what the later tasks assume and nothing else:

- `uname -a`, `whoami`, `git --version`, `nproc`, `df -h .`
- `actions/setup-node@v4` with `node-version: 20` → `node -v`, `npm -v`
- `npm ci` in `scripts/probe-webui`, `npx playwright install chromium`, then launch Chromium and
  print its version — the actual Tier 2 gate
- `sudo -n true` to record whether passwordless sudo exists at all

A job that queues forever means the Default runner group does not include `KMM-Argus` → stop and
raise it with whoever owns the org runners. Delete this workflow before the PR; it exists to turn
three assumptions into facts, not to ship.

### Task 3 — Fix `npm run lint` so it works on a clean checkout

`argus-webui/package.json`:

```diff
- "lint": "tsx scripts/lint-tokens.ts && tsc --noEmit",
+ "lint": "npm run tokens && tsx scripts/lint-tokens.ts && tsc --noEmit",
```

Mirrors what `build` already does. Independent of CI — it fixes `npm run lint` for anyone on a fresh
clone. Do this before Task 5 so the new job is not green only by accident of step ordering.

### Task 4 — Named scripts for the three self-contained probes

`scripts/probe-webui/package.json` declares only `ws` and `ui`. Add the three that CI will run, so
the workflow stays a one-liner and the probe set has one place to change:

```json
"probe:follow-tail": "node follow-tail-probe.js",
"probe:related-logs": "node related-logs-probe.js",
"probe:version": "node version-probe.js",
"probes": "npm run probe:version && npm run probe:related-logs && npm run probe:follow-tail"
```

Cheapest first, so a broken `dist/` fails in one second rather than six. Also update
`scripts/probe-webui/README.md`: its opening line says "Not part of CI — there is no consumer app in
CI to host the server", which becomes half true. Keep that sentence as the reason `ui-probe.js` and
`ws-probe.js` remain manual (#17 Tier 3, explicitly out of scope) and say that the three fake-device
probes now run in `verify-webui.yml`.

### Task 5 — `.github/workflows/verify-webui.yml`

```yaml
name: Verify (Web UI)
permissions:
  contents: read
on:
  pull_request:
    branches: [main]
    paths:
      - 'argus-webui/**'
      - 'scripts/probe-webui/**'
      - '.github/workflows/verify-webui.yml'
  workflow_dispatch:
jobs:
  webui:
    runs-on: [self-hosted, android-build]
    timeout-minutes: 20
```

Steps, in order:

1. `actions/checkout@v4`
2. `actions/setup-node@v4` — `node-version: 20`, `cache: npm`, and **`cache-dependency-path`
   listing both `argus-webui/package-lock.json` and `scripts/probe-webui/package-lock.json**`. The
   repo has three lockfiles (root doc-tooling, webui, probes); without an explicit path the npm cache
   keys off the wrong one.
3. `actions/cache@v4` on `~/.cache/ms-playwright`, keyed
   `${{ runner.os }}-playwright-${{ hashFiles('scripts/probe-webui/package-lock.json') }}`. The
   lockfile pins Playwright 1.60.0, so the key moves exactly when the browser needs to.
4. `npm ci` in `argus-webui`
5. `npm run lint` — after Task 3 this is self-sufficient
6. `npm test` — 88 assertions, sub-second
7. `npm run build` — produces the `dist/` the probes serve; also the only thing that type-checks the
   real production build
8. `npm ci` in `scripts/probe-webui`
9. `npx playwright install chromium` (no `--with-deps`; see the fallback above)
10. `npm run probes` in `scripts/probe-webui`
11. `actions/upload-artifact@v4` with `if: failure()` for `scripts/probe-webui/last-failure.png` —
    all three probes already screenshot on failure, and a probe failure is unreadable without it

Match the comment style of the existing two workflows: `verify.yml` and `verifyIos.yml` both explain
*why* their triggers are shaped the way they are. State here that the `paths` filter keeps Kotlin-only
PRs off this job, and note the consequence you accepted — **a skipped paths-filtered workflow reports
no status, so `Verify (Web UI)` cannot be made a required check without a no-op guard job.** That
trade is deliberate; writing it down stops it being rediscovered as a bug.

### Task 6 — `verify.yml` → self-hosted

```diff
-    runs-on: ubuntu-latest
+    runs-on: [self-hosted, android-build]
```

and insert, after the `actions/setup-java@v4` step:

```yaml
      - name: Setup Android SDK
        uses: android-actions/setup-android@v3
```

Nothing else changes: the Gradle argument list, `:verifyVersionPins`, `gradle/wrapper-validation-action@v3`
and `gradle/actions/setup-gradle@v3` all work unchanged. Confirmed no Gradle script in the repo shells
out to `git` (grep over every `*.kts` finds only SCM URL strings in the POM blocks), so the checkout
mode is irrelevant either way.

Add a comment recording the two things a reader will otherwise get wrong: the SDK step is needed
because the self-hosted box does not preinstall it, and the runner is **shared with
`canvas_control_mobile`** — whose nightly fires at 04:00 UTC and whose publishes are manual — so a
PR can queue behind an Android release build instead of starting immediately.

`verifyIos.yml` and `publishToMavenCentral.yml` are untouched. Both need Xcode: `iosSimulatorArm64Test`,
`assembleArgus-iosReleaseXCFramework`, `swift package compute-checksum`. There is no Apple
self-hosted runner. Splitting the non-Apple publications out of the release workflow onto Linux would
be a separate change with real release risk and is not in scope.

## Verification

- **Task 2 is itself the verification** for runner reachability, Node availability, and whether
  Chromium launches. Do not build Tasks 5–6 on assumptions it can settle.
- **Locally, from a clean tree** — every number in the table above is reproducible:
  `cd argus-webui && npm ci && npm run lint && npm test && npm run build`, then
  `cd ../scripts/probe-webui && npm ci && npx playwright install chromium && npm run probes`.
  Task 3 is verified by `npm run lint` passing *before* any `npm run build` has ever run — delete
  `argus-webui/src/design/tokens.json` first, or it proves nothing.
- **In CI**: push the branch and open the PR. `Verify (Web UI)` must run (the PR touches
  `argus-webui/**`) and `Verify (JVM/Android)` must go green on the self-hosted runner. Check the
  job's `runner_name` is `Aveli-Gazan-Android`, not a GitHub-hosted fallback.
- **Prove the paths filter both ways.** A Kotlin-only commit must show `Verify (Web UI)` skipped;
  a `argus-webui/**` commit must show it running. Both directions, or the filter is untested.
- **Prove the probe job can actually fail.** Temporarily break something the probes assert — e.g.
  point `fake-device.js`'s `APP_INFO.argusVersion` at a value the TopBar cannot render — push, and
  confirm red plus an uploaded `last-failure.png`. Revert. A gate never seen failing is not a gate;
  this is the same reason the crash-fix work insisted on running the test pre-fix.
- **Flake check before trusting it as blocking.** Re-dispatch `Verify (Web UI)` ~5 times on the
  branch. The assertions are timing-sensitive scroll measurements and the shared runner is noisier
  than a laptop. Any intermittent failure → add a settle-and-retry around the affected assertion
  rather than raising `SETTLE_MS` globally.

## Risks

- **Default runner group visibility** — the only hard blocker, and Task 2 finds it in one dispatch.
- **Chromium system libs on the box** — fallback documented above; worst case the probe job runs on
  `ubuntu-latest` and Tier 1 still lands self-hosted.
- **Runner contention** — one Linux runner shared with `canvas_control_mobile`. Argus PR checks may
  queue. Nothing to fix here; worth knowing before someone reports "CI is stuck".
- **`~/.gradle` is shared across repos on that box.** `git clean -ffdx` handles the workspace, not
  the Gradle user home. If Argus starts seeing cache weirdness that `ubuntu-latest` never showed,
  this is the first place to look.
- **Probe flake as a merge blocker.** Mitigated by the flake check above; if it does turn noisy, the
  reversible move is `continue-on-error: true` on step 10 alone, not deleting the job.

## Out of scope

emulator job running the sample app. The README note explaining why they are manual stays as the
record.
