# argus-webui CI + self-hosted runners — Shaping Notes

## Scope

Two things that happen to touch the same files.

**1. Close the hole from [#17](https://github.com/lynxal/KMM-Argus/issues/17).** `argus-webui` had no
CI job of any kind. `verify.yml` was Gradle-only, so a PR could break the whole Web UI — including
88 vitest assertions that already existed and passed locally — and CI stayed green. Every DOM-layer
bug in this UI so far was caught by a human driving a browser: #13's verification was a Playwright
harness built in a scratchpad and deleted after the run, and #15 was found by hand on a device.

**2. Move Argus CI onto the org's self-hosted runners** wherever Apple hardware is not required.
This half was investigated and **declined on evidence** — see "The self-hosted runner question,
answered" below.

Delivered: `.github/workflows/verify-webui.yml` running lint, typecheck, vitest and three headless
Chromium probes on `ubuntu-latest`; all four workflows left on GitHub-hosted runners; and a real bug
fixed on the way — `npm run lint` did not work on a clean checkout.

## Decisions

- **Separate `verify-webui.yml`, paths-filtered** to `argus-webui/**` + `scripts/probe-webui/**`,
  rather than a second job inside `verify.yml`. Kotlin-only PRs skip it entirely. Accepted cost,
  recorded in the workflow's own comments: GitHub reports **no status** for a skipped paths-filtered
  workflow, so this check cannot be made required in branch protection without a no-op guard job.
- **All three self-contained probes**, not just the one #17 named. `follow-tail-probe.js`,
  `related-logs-probe.js` and `version-probe.js` all fake the device through `fake-device.js` and
  need only a built `dist/`. Measured 6.5 s + 2.2 s + 1.0 s — one Chromium download covers all
  three, so running only `follow-tail` would have bought nothing.
- **Blocking from the start**, no `continue-on-error`. #17 suggested landing Tier 2 non-blocking and
  promoting it later; all three probes passed first try locally with 400 ms settles and no retries,
  and a non-blocking check is a check nobody reads. Reversible: `continue-on-error: true` on the
  probe step alone if the shared runner turns out noisier than a laptop.
- **No workflow moves to a self-hosted runner.** The shaped intent was `verify.yml` →
  `[self-hosted, android-build]`; the probe below showed that runner cannot serve this repo, and that
  the reason it cannot is one worth respecting rather than overriding. `verifyIos.yml` and
  `publishToMavenCentral.yml` were never candidates — `iosSimulatorArm64Test`,
  `assembleArgus-iosReleaseXCFramework` and `swift package compute-checksum` all need Xcode and
  there is no Apple self-hosted runner.
- **Fix `npm run lint` rather than paper over it in CI.** `npm run tokens` prepended, mirroring what
  `build` already does, so `npm run lint` works for anyone on a fresh clone instead of only working
  because CI happened to build first.
- **Named probe scripts** in `scripts/probe-webui/package.json` (`probe:*` plus a `probes`
  aggregate, cheapest first) so the workflow stays a one-liner and the probe set has one place to
  change. `ws` and `ui` stay as they were.
- **Verified the runner empirically before building on it.** A throwaway push-triggered workflow
  (`_runner-probe.yml`, since deleted) was the only way to test reachability — the org runners API
  needs `admin:org`. It is what turned the migration from a one-line diff into a decision.

### What shaping established that was not obvious

- `[self-hosted, android-build]` → `Aveli-Gazan-Android`, runner group `default`, **Linux x64**,
  workspace `/home/github-runner/actions-runner-android/_work`. No repo in the org has repo-level
  runners, so these are org-level in the Default group.
- **The "no git on PATH" comments in `canvas_control_mobile` are stale.** Three of its workflows
  claim `actions/checkout` falls back to a tarball with no `.git`; its 2026-08-20 run log shows
  `/usr/bin/git`, `git clean -ffdx` and `git fetch --depth=1`. Nothing in Argus needs a REST-API
  workaround, and `git clean -ffdx` between runs means the persistent workspace cannot serve stale
  AGP `intermediates`.
- **The Android SDK is not preinstalled** the way it is on `ubuntu-latest`; `canvas_control_mobile`
  adds `android-actions/setup-android@v3` explicitly. Had the move happened, `verify.yml` would have
  needed that step too, since it builds `:sample:assembleDebug`. Recorded for whoever revisits this.
- **`npm run lint` failed on a clean checkout.** `argus-webui/tailwind.config.ts:2` imports
  `./src/design/tokens.json`, generated by `npm run tokens` and gitignored at `argus-webui/.gitignore:7`;
  `lint` was `tsx scripts/lint-tokens.ts && tsc --noEmit` with no tokens step →
  `error TS2307: Cannot find module './src/design/tokens.json'`. Nobody hit it because `build`
  already runs `tokens` first.
- **Tier 2 costs far less than #17 estimated.** From a clean `npm ci`: build 3.1 s, 88 tests in
  0.4 s, probes 1.0 s / 2.2 s / 6.5 s. All three bind an ephemeral loopback port via
  `fake-device.js`, so there is no fixed-port collision on a shared runner. Playwright is
  lockfile-pinned, which is what makes the browser cache key stable.
- **The runner is shared with `canvas_control_mobile`**, whose nightly fires at 04:00 UTC and whose
  publishes distribute to Firebase. That sharing is what makes the security question below concrete
  rather than theoretical.

## The self-hosted runner question, answered

The probe job (`32358939545`) sat `queued` for 17 minutes and was never dispatched: `steps=0`,
`runner_id=0`, empty `runner_name`, no check-run annotations, and `GET /actions/runs/{id}/logs` →
404. There were no logs because nothing ever ran.

Ruled out, in order: the label (the job reports `labels=["self-hosted","android-build"]`,
byte-identical to a successful `canvas_control_mobile` job); repo Actions policy
(`{"enabled":true,"allowed_actions":"all"}`); workflow registration (the push did create the run);
and runner contention (nothing queued or in progress anywhere in the org, the box idle since
06:49 UTC).

What was left is visibility:

| Repo | Visibility | Uses the runner |
|---|---|---|
| `KMM-Argus` | **public** | queues forever |
| `canvas_control_mobile` | private | yes |
| `canvas_hub_core_application` | private | yes |
| `canvas_firmware` | private | yes |

Argus is the only public repo in the set. GitHub runner groups carry an **"Allow public
repositories"** setting that is **off by default**, and a job from a repo the group will not serve
queues silently with no annotation — precisely the observed shape. Confirming it needs one look at
the Default group (id 1); the API path needs `admin:org`, which was not available.

**The decision, and why it is not just "unblock it".** The default exists for the exact situation
here. `verify.yml` triggers on `pull_request`, Argus is public, and `Aveli-Gazan-Android` is the box
that builds and Firebase-distributes Canvas's Android releases. Enabling public-repo access would
give fork PRs code execution next to that pipeline; "require approval for first-time contributors"
is a thin barrier against that blast radius. So Argus stays on GitHub-hosted runners: the runners
are not unavailable so much as correctly withheld.

Two paths were considered and not taken, recorded so they need not be rediscovered — flipping the
group setting and accepting fork-PR risk, and a `runs-on` expression that sent only
`workflow_dispatch` runs to the box while forks stayed on `ubuntu-latest`. The second is viable if
the self-hosted minutes are ever actually wanted; it still needs the group setting changed.
